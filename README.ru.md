# Utka 🦆

[![OpenTimestamps](https://img.shields.io/badge/OpenTimestamps-anchored-blue.svg)](https://opentimestamps.org)
[![License](https://img.shields.io/badge/License-MIT-green.svg)](LICENSE)
[![Node](https://img.shields.io/badge/Node-24%2B-brightgreen.svg)](https://nodejs.org)

**Utka** — модульный комплекс управления прокси-инфраструктурой на базе [Xray-core](https://github.com/XTLS/Xray-core). Обеспечивает централизованное управление распределёнными узлами, динамическими клиентскими учётными записями, маршрутизацией через несколько инбаундов, раздачей подписок (VLESS, Clash, Sing-box) и учётом трафика с двуязычным клиентским порталом, панелью администратора и консольным CLI.

---

## Архитектура

Utka состоит из изолированных специализированных сервисов, способных работать как в едином контейнере, так и масштабироваться независимо:

```
                          ┌───────────────────────────┐
                          │   Authentik IdP (OIDC)    │
                          └─────────────┬─────────────┘
                                        │
┌───────────────────────────────────────┼────────────────────────────────────────┐
│ Комплекс Utka                         │                                        │
│                                       ▼                                        │
│  ┌───────────────────────┐  ┌───────────────────────┐  ┌────────────────────┐  │
│  │       utka-web        │  │       utka-sub        │  │      utka-cli      │  │
│  │ (Панель и дашборд)    │  │ (Сервер подписок)     │  │ (Консольный CLI)   │  │
│  └───────────┬───────────┘  └───────────┬───────────┘  └──────────┬─────────┘  │
│              │                          │                         │            │
│              └──────────────────────────┼─────────────────────────┘            │
│                                         ▼                                      │
│                             ┌───────────────────────┐                          │
│                             │ База данных PostgreSQL│                          │
│                             └───────────┬───────────┘                          │
│                                         │                                      │
│                             ┌───────────▼───────────┐                          │
│                             │       utka-core       │                          │
│                             │  (Фоновый демон sync) │                          │
│                             └───────────┬───────────┘                          │
└─────────────────────────────────────────┼──────────────────────────────────────┘
                                          │ gRPC API
                                          ▼
                             ┌─────────────────────────┐
                             │        Xray-core        │
                             │(VLESS, Reality, WS, gRPC│
                             └─────────────────────────┘
```

1. **`utka-core`**: Автономный фоновый демон синхронизации. Проверяет доступность узлов, опрашивает статистику потребления трафика через gRPC API Xray, сохраняет историю в PostgreSQL и актуализирует клиентов в памяти Xray.
2. **`utka-sub`**: Высокопроизводительный HTTP-сервер подписок. Раздаёт конфигурации по ссылкам (`/s/:token`, `/api/sub/:token`) в форматах raw base64 VLESS, профилях Clash/Mihomo YAML и Sing-box JSON со стандартными заголовками `Subscription-Userinfo`. Содержит адаптивный клиентский веб-портал с тёмной/светлой темой и генератором QR-кодов.
3. **`utka-web`**: Веб-интерфейс на базе Next.js App Router (панель администратора и личный кабинет пользователя). Управляет нодами, инбаундами клиентов и авторизацией через Authentik OIDC.
4. **`utka-cli` (`bin/utka`)**: Консольный инструмент управления без графической оболочки (добавление/удаление пользователей, принудительная синхронизация, проверка сокетов, вывод QR-кода прямо в терминал).

## Ключевые возможности

- **Мульти-инбаунд маршрутизация**: Автоматическая выдача клиенту нескольких путей выхода (например, релей через Франкфурт, московский WARP и прямой локальный выход) с изолированными правилами роутинга.
- **Универсальные подписки**: Нативная совместимость с клиентами Clash Verge Rev, Mihomo Party, Clash Meta, Hiddify, Karing, ClashMi, v2rayN и Sing-box.
- **Маскировка трафика (Stealth)**: Работа поверх легитимных HTTPS-сервисов (Git, SSO, облако) через WebSocket path multiplexing и протокол XTLS Reality.
- **Интеграция с Authentik (OIDC)**: Централизованная авторизация пользователей с автоматической синхронизацией прав администратора из групп Authentik.
- **Точный учёт трафика**: Детализированная статистика загрузки и отдачи, история сессий и поддержка квот.
- **Криптографическая верификация**: Все коммиты и теги подписываются SSH-ключами и фиксируются в блокчейне Bitcoin через OpenTimestamps.

## Быстрый старт

### 1. Требования

- Docker / Podman с поддержкой Compose
- PostgreSQL 16+
- Xray-core 25.10+ (с включённым API через gRPC или UNIX-сокет)

### 2. Настройка конфигурации

Скопируйте файл переменных окружения:

```bash
cp .env.example .env
```

Заполните ключевые параметры в `.env`:

```ini
AUTH_URL=https://dash.example.com
AUTH_SECRET="generate_with_openssl_rand_base64_32"

# Authentik OIDC
AUTHENTIK_CLIENT_ID="utka-client-id"
AUTHENTIK_CLIENT_SECRET="utka-client-secret"
AUTHENTIK_ISSUER="https://auth.example.com/application/o/utka/"

# PostgreSQL
DATABASE_URL="postgresql://utka:secret@postgres:5432/utka_db?schema=public"

# Основной узел Xray
XRAY_SERVER_DOMAIN_OR_IP="vpn.example.com"
XRAY_API_URL="unix:///run/xray/xray-api.sock"
```

### 3. Запуск через Docker Compose

```bash
docker compose up -d
```

Применение миграций базы данных:

```bash
docker compose exec utka npx prisma migrate deploy
```

## Управление через CLI

В состав Utka входит консольная утилита `utka`:

```bash
# Проверка статуса демона, подключения к БД и сокету Xray
utka status

# Принудительная синхронизация пользователей из БД в память Xray
utka sync

# Список всех пользователей и объём потреблённого трафика
utka user list

# Добавление нового клиента
utka user add Alice

# Просмотр информации о пользователе, ссылки подписки и QR-кода в терминале
utka user get Alice

# Отзыв доступа и удаление пользователя
utka user delete Alice
```

## Политика безопасности

Все официальные релизы и коммиты подписываются с помощью SSH-ключей и фиксируются в блокчейне Bitcoin с помощью OpenTimestamps.

Проверка подписей локально:

```bash
git config gpg.ssh.allowedSignersFile .allowed_signers
git log --show-signature
```

Об обнаруженных уязвимостях сообщайте в соответствии с [SECURITY.md](SECURITY.md).
